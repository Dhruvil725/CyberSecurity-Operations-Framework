## 2. Purpose

This document serves as the master index for all Incident Response (IR) playbooks maintained within the IR-DOCUMENTATION repository.

The purpose of this index is to:

- Provide centralized navigation across all IR playbooks
- Standardize access to operational procedures
- Support SOC, IR, Threat Intelligence, and MSSP operations
- Improve analyst response speed during active incidents
- Maintain audit-ready documentation references
- Ensure version-controlled playbook governance
- Support NIST, ISO 27001, RBI, and CERT-In aligned IR operations

This index must be reviewed and updated whenever:

- A new playbook is added
- Existing playbooks are retired
- Major revisions occur
- New incident categories are introduced

---

## 3. Playbook Structure Overview

The playbook repository is organized by attack category and operational workflow.

Each playbook category typically includes:

| Playbook Type | Purpose |
|---------------|---------|
| Master Playbook | High-level incident response lifecycle |
| L1 Triage | Initial alert handling and validation |
| L2 Investigation | Deep investigation and scoping |
| L3 Forensics | Advanced forensic and malware analysis |
| Containment | Immediate and strategic containment actions |
| MITRE Mapping | ATT&CK framework mapping and hunting support |
| Specialized Procedures | Vendor, cloud, attribution, etc. |

# 5. Cross-Playbook Operational Guidance

Some incidents may require activation of multiple playbooks simultaneously.

---

## 5.1 Multi-Playbook Activation Examples

| Scenario | Required Playbooks |
|----------|-------------------|
| Ransomware with cloud compromise | Ransomware + Cloud |
| Web shell leading to lateral movement | Web App + Network Intrusion |
| Supply chain leading to APT activity | Supply Chain + APT |
| Credential theft with data exfiltration | Credential Attack + Data Breach |
| VPN zero-day exploitation | Zero-Day + Network Intrusion |

# 6. Playbook Governance

All playbooks must:

- Be version controlled
- Follow approved IR documentation standards
- Undergo quarterly review
- Be updated after major incidents
- Be aligned to:
  - NIST CSF
  - ISO 27001
  - RBI Cyber Security Framework
  - CERT-In guidance

---

# 7. Playbook Usage Requirements

During active incidents:

- Analysts must follow documented workflows
- Deviations must be documented and approved
- Evidence handling must follow CoC procedures
- All containment actions must be logged
- Executive communication must use approved templates
